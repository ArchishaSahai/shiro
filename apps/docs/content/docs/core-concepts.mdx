# Core Concepts

Shiro has a small set of runtime concepts. Each one owns a different part of execution.

## Engine

The engine is the long-lived runtime service. It owns providers, plugins, registries, sessions,
approval services, event buses, and trace exporters.

Use it when you need a stable entrypoint for many runs.

## Runner

The runner owns one run. It tracks messages, tool calls, handoffs, approvals, memory reads,
validation attempts, and emitted events.

Use it indirectly through `engine.execute()` or streaming APIs.

## Agent

An agent is a declarative unit of behavior: name, instructions, tools, handoffs, provider
preferences, memory policy, and output shape.

Do not put per-user state on the agent.

## Tool

A tool is a typed side effect. The model may request it, but Shiro executes it.

Use tools for operations that need code: lookups, writes, calculations, workflow calls, or
internal service requests.

## Provider

A provider adapts a model API to Shiro. Providers should not know about Studio, approvals,
memory, or handoffs.

## Trace

A trace is a structured record of a run. It is the source of truth for debugging.

## Comparison

| Concept | Lifetime | Owns |
| --- | --- | --- |
| Engine | process | shared services |
| Runner | one run | execution state |
| Agent | configuration | behavior |
| Tool | call | side effect |
| Trace | run history | observability |
