# Multi-Agent

Multi-agent execution in Shiro is built on handoffs. A handoff transfers control to another
agent while the same runner continues the run.

## Why handoffs exist

Different domains often need different tools and rules. A support agent should not have direct
access to billing mutation tools unless it is also responsible for billing decisions.

## Example

```ts
const support = new Agent({
  name: "support",
  handoffs: [billing, research],
});
```

## When to use handoffs

Use a handoff when the active agent no longer has the right responsibility, tools, or approval
policy.

Good examples:

- support to billing
- triage to research
- planning to deployment
- incident intake to remediation

## Best practices

- Keep handoff targets explicit.
- Trace every handoff.
- Give specialist agents narrower tools.
- Avoid circular handoff paths unless you can explain why.

## Common mistakes

- Creating many agents for prompt organization only.
- Giving every agent every tool.
- Implementing handoffs outside the runner.
