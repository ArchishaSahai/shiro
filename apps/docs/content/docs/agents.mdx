# Agents

An agent is a declarative description of behavior. It should say what the model is responsible
for, which tools it can use, which agents it can hand off to, and what shape the final output
must have.

```ts
const support = new Agent({
  name: "support",
  instructions: "Help users resolve account and billing questions.",
  tools: [lookupInvoice, issueRefund],
  handoffs: [billing],
});
```

## Why agents are declarative

The runner owns execution. Agents should not contain request-specific state or hidden control
flow. Keeping agents declarative makes runs easier to trace, test, and hand off.

## When to create multiple agents

Use multiple agents when responsibility changes, not just when prompts get long. A billing
agent, research agent, and deployment agent may have different tools, approvals, and output
requirements.

## Best practices

- Give each agent a narrow responsibility.
- Keep tool access explicit.
- Use handoffs for domain changes.
- Keep user state in sessions.
- Validate final output when another system consumes it.

## Common mistakes

- Using one agent for every domain.
- Adding tools that the agent should never call.
- Mutating agent instructions per user.
- Hiding business rules inside a long prompt.
