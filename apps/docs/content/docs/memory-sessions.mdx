# Memory Sessions

Sessions hold durable context for a user, workflow, or conversation. Memory is the runtime
layer that retrieves and persists useful context around a run.

## Why sessions exist

Agents should be reusable definitions. If you put conversation state on an agent, the agent
becomes tied to one user. Sessions keep state separate from behavior.

## Example

```ts
await engine.execute(agent, input, {
  sessionId: "support_1842",
});
```

## What belongs in a session

- conversation history
- user-specific context
- prior tool results worth reusing
- decisions that affect future runs

## What does not belong

- provider credentials
- agent instructions
- global application state
- large raw documents

## Best practices

- Use stable session IDs.
- Summarize long histories.
- Store source metadata with retrieved facts.
- Trace memory reads and writes.

## Common mistakes

- Treating memory as a prompt dump.
- Persisting every token from every run.
- Mixing sessions across users.
