# Studio

Studio is how you **see** a Shiro run. It is not a second orchestrator and not a chatbot. It
loads sample traces (and imported JSON exports) so you can navigate timelines, graphs, tools,
approvals, memory, metrics, and raw events while you build agents.

If [Tracing](/docs/tracing) is the source of truth, Studio is the workspace built on top of it.

## Why Studio exists

Text logs answer “did something fail?” They rarely answer:

- Which provider call requested this tool?
- Did approval pause the run before `issueRefund`?
- What memory was loaded before the second model call?
- Which handoff changed the active agent?

## What Studio is (and is not)

| Studio is                        | Studio is not                 |
| -------------------------------- | ----------------------------- |
| An observer of runs and traces   | An execution engine           |
| A timeline + graph + inspectors  | A replacement for your app UI |
| A place to load and compare runs | A prompt playground           |

## Launching Studio

### From a scaffolded project

```bash
pnpm add -D @shiro/cli @shiro/studio
pnpm studio
# or
pnpm exec shiro dev --port 3001
```

### From the monorepo

```bash
pnpm --filter @shiro/studio dev
# or
pnpm exec shiro dev
```

## Workspace layout

The shipped Studio UI is a dashboard:

| Area           | Role                                           |
| -------------- | ---------------------------------------------- |
| Sidebar        | Jump to Sessions, Runs, Tracing, Graph, …      |
| Run explorer   | Select among loaded / sample runs              |
| Metrics        | Tokens, cost, latency, provider/tool timings   |
| Execution log  | Chronological event lines for the selected run |
| Timeline       | Ordered spans (provider, tool, handoff, …)     |
| Graph          | Agent / tool / approval nodes for the run      |
| Tool inspector | Arguments, status, and results for tool calls  |
| Approvals      | Policy and decision details                    |
| Memory         | Session / memory records for the run           |
| Trace viewer   | Searchable events and span details             |

Use **Import** in the header to load a JSON trace export produced by `JsonTraceExporter`.

## Sample traces

Studio ships with demo runs that exercise tools, handoffs, approvals, and memory so the panels
are populated before you wire your own exporter.

| Trace              | What it exercises                        |
| ------------------ | ---------------------------------------- |
| `customer-support` | Tools, handoff, approval, Markdown reply |
| `refund`           | Destructive tool + approval              |
| `travel-agent`     | Multi-tool itinerary                     |
| `research`         | Memory retrieve/compact + handoff        |
| `multi-agent`      | Ops → research → security                |

## Wiring your app

1. Create a shared `TraceManager` on the [engine](/docs/engine)
2. Execute through `engine.execute(...)`
3. Export JSON with `JsonTraceExporter`
4. Import the file in Studio

```ts
import { Engine, JsonTraceExporter, TraceManager } from "@shiro/core";

const traces = new TraceManager();
const engine = new Engine({ events: traces });
// ... plugins, agent, execute ...
const json = await traces.export(new JsonTraceExporter());
```

## Debugging workflows

| Symptom                     | Where to look first                           |
| --------------------------- | --------------------------------------------- |
| Slow run                    | Timeline spans; metrics provider vs tool time |
| Wrong tool args             | Tool inspector                                |
| Agent “forgot” prior turn   | Memory explorer + session id                  |
| Risky tool ran unexpectedly | Approval center + tool `requiresApproval`     |
| Confusing multi-agent path  | Execution graph + handoff events              |
| Need a bug report artifact  | Trace viewer / JSON export                    |

## Common mistakes

- Expecting Studio to see tools you called outside the runner
- Debugging only from application logs after adopting traces
- Treating Studio as the place to _define_ agents (define them in code; inspect them here)
- Forgetting to install `@shiro/studio` when using `shiro dev` outside the monorepo
