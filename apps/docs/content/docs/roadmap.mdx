# Roadmap

The roadmap is organized around runtime clarity. New features should make runs easier to
control, inspect, and reproduce.

## Runtime

- stronger retry policy primitives
- first-class timeout configuration
- richer approval adapters
- more output repair controls

## Studio

- trace comparison
- saved run views
- approval audit history
- memory diffing
- tool latency breakdowns

## Providers

- more provider adapters
- provider capability metadata
- normalized usage reporting

## Observability

- OpenTelemetry exporter
- JSON trace snapshots
- external trace sinks
- run-level metrics

## Principles

Shiro should avoid features that hide execution. The runtime should expose enough structure for
developers to understand why a run behaved the way it did.
