# Plugins

Plugins install behavior into the engine: providers, exporters, memory backends, approval
services, or lifecycle subscribers.

## Why plugins exist

The engine needs extension points, but direct access to internals makes upgrades fragile.
Plugins receive a public context and register capabilities through stable APIs.

```ts
const engine = new Engine({
  plugins: [studioPlugin(), customTraceExporter()],
});
```

## When to write a plugin

Write a plugin when behavior should be installed once and reused across many runs.

Good plugin candidates:

- trace exporters
- provider bundles
- memory backends
- approval adapters
- Studio integrations

## Common mistakes

- Mutating engine internals.
- Registering request-specific state in a plugin.
- Hiding provider calls inside plugin hooks.
