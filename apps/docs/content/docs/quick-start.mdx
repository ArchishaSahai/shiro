# Quick Start

This guide creates one agent with one tool. The goal is not to build a full application; it is
to see how Shiro moves execution through the runtime.

## 1. Create an engine

The engine owns shared runtime services. Create it once and reuse it.

```ts
import { Engine } from "@shiro/core";
import { openai } from "@shiro/openai";

const engine = new Engine({
  providers: [openai({ model: "gpt-5" })],
});
```

## 2. Define a tool

Tools are typed side effects. They run inside the Shiro lifecycle, so they can be traced,
timed out, approved, or retried.

```ts
import { tool } from "@shiro/core";

const weather = tool({
  name: "weather",
  description: "Look up current weather for a city.",
  execute: async ({ city }: { city: string }) => {
    return { city, summary: "Clear", temperatureC: 27 };
  },
});
```

## 3. Define an agent

Agents describe behavior. Avoid storing user state on the agent itself.

```ts
import { Agent } from "@shiro/core";

const agent = new Agent({
  name: "support",
  instructions: "Help users with concise, factual answers.",
  tools: [weather],
});
```

## 4. Execute a run

```ts
const result = await engine.execute(agent, "Should I bring an umbrella in Pune?");
console.log(result.output);
```

## What happens

- the engine creates a runner
- the runner prepares session context
- the provider receives the agent instructions and current messages
- the model may request the weather tool
- Shiro executes the tool and records a span
- the final answer is returned with trace data

## Best practices

- Keep the engine outside request handlers.
- Keep tools small and typed.
- Add tracing before adding multiple agents.
- Use sessions when a conversation spans more than one request.

## Common mistakes

- Calling tools directly from application code.
- Letting the model invent tool argument shapes.
- Recreating the engine for every run.
