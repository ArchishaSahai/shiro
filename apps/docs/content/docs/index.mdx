# Shiro

Shiro is a TypeScript runtime for agent execution. It owns the loop that decides when to call a
provider, execute a tool, pause for approval, switch agents, read memory, validate output, and
emit trace events.

Your application defines the workflow. Shiro runs it.

## What Shiro gives you

- a long-lived `Engine` for shared runtime services
- a per-run `Runner` for execution state
- typed tools with lifecycle events
- provider adapters behind one contract
- sessions and memory for durable context
- handoffs between agents
- approval pauses for risky actions
- structured output validation
- traces that Studio and exporters can consume

## Why it exists

Most agent projects begin as a provider call and a tool function. The hard part comes later:
timeouts, retries, handoffs, approvals, memory, debugging, and explaining what happened when a
run fails. Shiro puts those concerns in the runtime instead of scattering them through API
routes, queues, and one-off logging code.

## Mental model

```txt
Engine -> Runner -> Provider -> Tools -> Approvals -> Memory -> Output -> Trace
```

The engine is long-lived. A runner is created for one execution. The trace records what the
runner did.

## When to use Shiro

Use Shiro when your agent needs more than a single model call: tools, sessions, approval,
handoffs, structured output, or run inspection.

If you only need a one-off completion, call the provider directly.
