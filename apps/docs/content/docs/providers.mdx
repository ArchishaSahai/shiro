# Providers

A provider turns a Shiro model request into a vendor API call. It should be small: accept
messages and model options, return model output and tool requests, and report usage.

## Why providers are isolated

Provider APIs change. Runtime behavior should not. Shiro keeps vendor-specific code behind an
adapter so tools, memory, approvals, handoffs, and Studio do not depend on one model SDK.

## Example

```ts
const engine = new Engine({
  providers: [openai({ model: "gpt-5" })],
});
```

## What providers should not own

- memory persistence
- approval decisions
- tool execution
- Studio rendering
- handoff policy

## Best practices

- Keep provider configuration close to engine setup.
- Record token usage and latency.
- Normalize errors at the adapter boundary.
- Avoid leaking vendor-specific response shapes into tools.
