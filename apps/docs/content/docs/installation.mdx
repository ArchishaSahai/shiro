# Installation

Install the core runtime and the provider package you will use.

```bash
npm install @shiro/core @shiro/openai zod
```

`zod` is commonly used for tool `parameters` and structured `output` schemas because it exposes
a `.parse()` method Shiro can call.

## Packages

| Package         | Purpose                                                             |
| --------------- | ------------------------------------------------------------------- |
| `@shiro/core`   | Engine, runner, agents, tools, memory, sessions, tracing, approvals |
| `@shiro/openai` | OpenAI provider + plugin (`OpenAIPlugin`, `OpenAIProvider`)         |
| `@shiro/studio` | Studio app for inspecting runs and traces                           |
| `@shiro/cli`    | Project scaffolding and local Studio launch                         |

## Environment

Keep credentials out of agent files.

```bash
export OPENAI_API_KEY=...
```

## Verify the install

This matches the pattern used in the repo’s basic example: create an engine, install the OpenAI
plugin, define an agent with a provider id, execute once.

```ts
import { Agent, Engine } from "@shiro/core";
import { OpenAIPlugin } from "@shiro/openai";

const engine = new Engine();
engine.use(
  new OpenAIPlugin({
    apiKey: process.env.OPENAI_API_KEY!,
    model: "gpt-5",
  })
);

const agent = new Agent({
  name: "hello",
  instructions: "Answer in one short sentence.",
  provider: "openai",
});

const result = await engine.execute(agent, "What does the Shiro engine own?");
console.log(result.output);
```

If this throws on missing API keys or provider registration, fix configuration before adding
tools or Studio.

## Scaffold with the CLI

```bash
npx @shiro/cli init my-agent
cd my-agent
npm run dev
```

`shiro init` creates a project. `shiro dev` runs diagnostics and launches [Studio](/docs/studio).
See [CLI](/docs/cli).

## Common mistakes

- Installing `@shiro/openai` but never calling `engine.use(new OpenAIPlugin(...))`
- Creating an agent without `provider`
- Reading secrets from source files committed to git
- Creating a new engine on every request — see [Engine](/docs/engine)
